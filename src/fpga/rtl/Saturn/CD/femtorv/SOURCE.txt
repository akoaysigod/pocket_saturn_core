Used by      rtl/Saturn/CD/CDB_HLE.sv when CDB_FEMTORV is defined (requires CD_HLE): it runs the CD block HLE firmware
             (and the SMPC firmware with SMPC_FW) in place of the PicoRV32, behind the adapter CDB_HLE_FEMTORV at the
             end of CDB_HLE.sv. Without CDB_FEMTORV this file is empty after preprocessing.

Local changes (femtorv32_quark.v, each marked "CDB_HLE local change"):
1. The file is inside `ifdef CDB_FEMTORV and sets two of the quark's own options for the CD block:
   NRV_TWOLEVEL_SHIFTER (shifts move 4 bits per clock) and NRV_COUNTER_WIDTH 1 (the cycle counter is read only by
   SYSTEM instructions; the firmware has none). Both are `undef'd again at the end of the file.
2. The register file: Quartus turned the array, read inside the state machine, into 1,024 registers. It is now two
   32 x 32 RAMs (module FemtoRV32_RegRAM, added at the end of the file), written as the array was, with a registered
   read port that loads rs1 / rs2 in exactly the clocks the state machine loaded them; nothing writes the register
   file in those clocks, so the behaviour is cycle for cycle the original's. The RAMs start at 0, which replaces the
   BENCH-only initial write of x0 (x0 is never written).
3. The load / store address adder is gone: a Store takes Simm in aluIn2 (it differs from Iimm in bits 4:0 only) and
   loadstore_addr is aluPlus; both are looked at only for a Load or a Store, where aluPlus is rs1 + Iimm / Simm as before.
4. The quark's two 32-bit adders (aluPlus, aluMinus) are one adder / subtractor: aluSub is high for SUB, SLT / SLTU
   (and the immediate forms) and the branches, which are the only users of the difference, its borrow (LT, LTU) and
   its zero test (EQ); ADD, ADDI, JALR and the load / store address have it low. LT, LTU, EQ and the result are the
   same functions of the operands as before.
Nothing else is changed (no other line of the upstream file differs).
