# Portable widened-counter regression

Run from any directory with Python 3 and Clang supporting UndefinedBehaviorSanitizer:

```
python3 tools/test_counter.py --source-dir src/fw/cdb --out /tmp/counter-check-001
```

Install `test_counter.py` and `counter_harness.c` together (for example under repository `tools/`). `--source-dir` must contain the actual repository `cdb_hle.c`, `hw.h`, `rt.h`, `smpc.h` and `cd_src.h`. The tool requires widened `int64_t DriveCounter` and the PR18 deadline-anchor change. It does not fetch or generate a replacement controller. `--out` must not exist; results are never overwritten. `--cc` selects Clang. No campaign paths, private ROM, FPGA tools or archived receipts are dependencies.

The output contains a read-only snapshot of all input source/header/tool bytes, compiled wide and mutant fixtures, full commands and logs, compiler/Python versions, macros, source/log/binary hashes, and `result.json`. Live inputs, snapshots and every generated compiler input (controller, adapted header, harness and copied headers) are rehashed at completion, including failure paths. Generated bytes must match their recorded precompile hashes; any change produces SOURCE_CHANGED and fails the run. Read-only permissions prevent ordinary accidental edits, not a privileged writer; final hashes enforce consistency. Preserve the entire output, not just its PASS line.

The harness includes the complete repository controller. It adapts MMIO and explicitly stubs cooperative SMPC and external source calls; it does not emulate the native CPU or APF. After actual CDB_Reset/SWReset it seeds a PLAY/idle checkpoint, synthetic one-track metadata and free buffers. Tests then call actual Drive_Run/CDB_Run/cd_main/cd_restart entrypoints. An arithmetic oracle sums delivered elapsed ticks; it does not reproduce the controller scheduler.

Required cases:

- Ten thousand representable pending-source calls, including zero elapsed, compare traces with a narrow-storage mutant derived from the same source. Twenty command/deadline/STOP/short timer-wrap scenarios compare three main-loop checkpoints each.
- 200 and 500 seconds of pending source using 10 ms samples preserve every tick of debt, followed by release with exact sector/read counts. Immediate source readiness is a stress stub, not a media-throughput model.
- Actual SEEK-stop and reset/cancel paths after prolonged debt; wide arithmetic boundary cases and a seeded debt below -2^40; restart disables deadline publication.
- Mandatory narrow mutant must compile and fail with UBSan's precise signed subtraction overflow; saturation mutant must compile and fail at step 19022 with the exact debt discrepancy. Compilation failures, timeouts or unrelated failures cannot satisfy controls. Original-source comparison is confined to representable normal traces, except the intentionally overflowing negative control.

This fix preserves accumulated debt instead of adopting a new timeout or forgiveness policy. Every timer sample must represent a nonnegative elapsed interval below 2^31 ticks. Negative or ambiguous long samples and missed complete 2^32 timer wraps remain unsupported. The 500-second test delivers small CDB_Run samples; separate main-loop tests cover short modulo wrap, not native multi-wrap behavior. CDB_Reset alone is not asserted to clear the external source adapter; explicit cancellation is tested separately. No complete startup/BSS, native stack, hardware, disc, CDDA or deadline-effectiveness claim follows.

The tested cumulative PR18+wide RV32 build increases public .text by 420 bytes and occupied static memory by 432 bytes, leaving 1868 bytes below the fixed stack top. This is a robustness change with code/runtime cost, not an optimization. Those figures belong to the recorded qualification toolchain/layout, not every build. Separate native timing, stack, BSS and complete-core qualification has completed for the cumulative PR18+counter image, as described below. A standalone upstream77 counter patch exists separately, but this portable suite deliberately requires the PR18 deadline parent used in the intended cumulative PR.

Generated-input integrity controls are reproducible with:

```
python3 tools/test_generated_input_guard.py --source-dir src/fw/cdb --out /tmp/counter-races-001
```

The wrapper invokes real Clang, then modifies generated `wide/controller.c` after successful compilation. All runtime checks must still complete, but final integrity must reject the run as `SOURCE_CHANGED`. A second control changes generated `wide/harness.c` and returns compiler failure; final integrity must still report the precise source change. Neither failure is accepted as an overflow/saturation negative. Expected hashes are calculated from intended snapshot-derived bytes, not reread from possibly modified generated files. Endpoint hashes detect persistent changes; they cannot prove absence of a transient change restored before rehashing. Run in an isolated output directory without another writer.

## Recorded integration qualification

The cumulative PR18+counter firmware was rebuilt and used in a full Cyclone V compile, fit, assembly and timing analysis with Quartus Standard 25.1std.0 Build 1129, seed 10 and eight workers. All four timing corners pass the same inherited clock/coverage checks as the matched upstream image: worst setup +0.096 ns and hold +0.106 ns. Resources are unchanged at 18,033 placed ALMs, 1,847 LABs, 283 M10Ks and 47 DSPs. Existing unconstrained external IO remains; this is not complete board timing coverage.

An exact-image native empty-source CD/SMPC run completed CDON, bootstrap/status, CDOFF, complete CD-BSS clearing and a second CDON/bootstrap/status in 70,202,608 cycles (1.286161 simulated seconds). Both statuses were `[0x0600, 0xffff, 0xffff, 0xffff]`; all 2,614 CD-BSS words were cleared. The lowest observed stack pointer was 89,776, leaving 1,532 bytes above occupied static memory in this fixture. This observation and a separate public call-graph assessment do not establish a whole-firmware maximum stack bound. Cold-start, BSS observer fault controls and 27 native wide-arithmetic boundary checks also passed.

Public-object native profiling measured PLAY calls at 313 to 350 cycles, pending-source calls at 467 to 523, and a two-sector release at 11,319 to 11,448. Actual public source-path scan and parse cases increased from 11,140 to 11,221 and 22,977 to 23,033 cycles respectively, with unchanged observed stack use. These bounded fixtures do not establish whole-game runtime cost. No ordinary-game failure, real-media throughput benefit, Pocket gameplay result or FPS improvement is established for this counter change.

This proposal contains public source and portable tests. **Maintainers must regenerate both controller firmware banks with their licensed build inputs and rebuild the FPGA core to deliver the change.** Editing `cdb_hle.c` alone does not alter the existing prebuilt firmware banks. Private firmware inputs, generated banks, complete ELF files and bitstreams are excluded from this proposal.
